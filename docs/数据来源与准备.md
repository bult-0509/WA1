# 数据来源与准备

数据项目：MetroFlow；作者原始发布记录及CC BY 4.0许可见 https://doi.org/10.6084/m9.figshare.28844942 。作者代码见 https://github.com/Ariza-Sun/MetroFlow 。论文DOI：10.1038/s41597-025-05416-8。

本项目使用2017年5月1日至8月31日的302站进出聚合表。它有3,788,892条记录、13列，不是七亿级个人交易原表，也不读取OD表。

从正式数据页下载MetroFlow.zip（约1.22GB），只提取下列四个文件至`data/raw/`：

| 发布包内位置 | 本地文件名 | 内容 |
|---|---|---|
| MetroFlow/metroData_InOutFlow.csv | metroData_InOutFlow.csv | 10分钟进出计数，217,442,845字节 |
| MetroFlow/stationInfo.csv | stationInfo.csv | 302站ID、源站名、坐标、邻接关系 |
| MetroFlow/MetaData/workday_calendar.csv | workday_calendar.csv | 123日工作日标记，包括调休 |
| MetroFlow/MetaData/shanghai_weatherHourly.csv | shanghai_weatherHourly.csv | 2,952小时的代表点天气 |

当前工作区已取得四个文件。首次数据核验使用按需读取压缩包的方法节约下载，完整原始证据留在需求资料中；课程复现可按上表手动提取，不必实现专门下载器。只演示系统时无需这些原文件，源码ZIP和便携包已经附带处理后数据。

在完整Python开发环境安装依赖后运行`python prepare_data.py`。它统一日期/时间和字段、检查缺失/重复/负值及分项和、排除六个计数缺损日、按小时和日聚合、关联日历及天气、计算KMeans分组。运行后`data/processed/quality.json`记录真实处理数量，`clusters/`包含分组和评价。

原始进出文件完整性核验记录：3,788,892行、13列、302站、123日、每日102时段。原始缺失单元格、重复键、负流量、分项不一致均为0。2017-05-04、05-08、05-09、06-16、06-27、06-28虽然网格完整但计数缺损；其余117日作为正常分析日期。

进站人次为全网主口径；进出相加不能称去重乘客人数。C/HBO/NHB是发布方推断标签。天气温度单位为°C，rain为mm，风速km/h；按城市代表点小时数据聚合，每日24小时必须完整。地图采用原始经纬度，参考系未说明；数据中的邻接连线仅用于空间关系展示。

## 10分钟边流量附件

项目后续收到`metro_map.html`、`stations.js`、`edges.js`和`data_flow_edges.js`四个配套文件，现存于`static/metro_map/`。附件包含302站、349条无向邻接边，以及2017年5月1日至12日的12天边流量；每个完整日有102个10分钟时段，5月8日只有101个。按主项目质量规则排除5月4日、8日和9日后，动画显示9个有效日。

这四个文件没有提供边流量的生成脚本或公式，无法从现有进出站表复算。因此动画只展示附件中的预生成边值；线宽和颜色表示相对强度，“边流量合计”不作为全网乘客量。附件也没有方向字段，邻接边按无向关系绘制。页面所需Leaflet脚本、样式和字体均随包保存，不访问在线底图。

所有原始CSV保留在开发机，均不装入代码ZIP或总包。数据处理结果保留完整范围，不以抽样减少站点或月份。
