# 本科项目精简说明

日期：2026-09-03。对应《需求冻结版项目规格》v1.1。

依据用户本轮要求：“在保留高级感的基础上剔除掉部分不适合出现在本科生项目的参数”。截图提供的反馈集中在目录过多、工程术语过重和答辩难解释，原图已备份到`docs/ai-process/本科项目精简反馈.png`。本轮修改由用户提出方向、Codex执行，仅调整规格，尚未开发程序。

## 本轮怎么改

| 原方案 | 当前方案 | 答辩时怎么说明 |
|---|---|---|
| 数据加载、质量、配置、版本清单和数据契约分散在多个模块 | 合并为一个数据处理模块，保留必要检查与汇总 | 读取数据，检查错误，再按小时和日期统计 |
| 独立的中间数据目录 | 原始数据与处理后数据两层；临时表按需重算 | 原始文件用于核对，汇总文件用于快速展示 |
| 人员配置、项目配置单独管理 | 人员信息写README和报告；少量固定设置写代码 | 四人分工清楚，项目参数保持固定 |
| 专门的运行管理模块，自动处理端口和实例 | 简单启动/关闭入口，遇到问题给中文提示 | 随包附带运行环境，换电脑双击即可打开 |
| 独立模型目录、输入哈希和模型清单 | 分组表、各组平均曲线、评价表放在处理后数据中 | 提前算好分组，现场直接查看 |
| KMeans加Ward、多阶段月份划分、多个评价与稳定性指标 | 只用KMeans，比较2–5组，保留轮廓系数 | 把曲线相似的站点放在一起，解释各组特点 |
| 统计量和专业符号密集展示 | 主界面显示关键数字，其余放明细和方法说明 | 先说分析问题，再用图和数字解释结论 |
| 专门的分段下载器、依赖哈希锁和发布清单程序 | README写数据准备方法，一份requirements.txt记录版本，简单打包脚本 | 数据从哪里来、怎样安装、怎样启动都能照说明完成 |
| 固定20秒/3秒/5秒性能门槛 | 另一台电脑上完成一次连续、可用的完整演示并记录 | 启动、切页、筛选、导出都实际测过 |
| 多层AI过程目录和索引表 | 按日期记录，附原始对话及关键版本 | 展示AI初版、用户意见、修改过程和结果 |

取消专项工程模块后，数据缺失、重复、异常日期、零分母、缺文件等必要检查仍然执行。哈希等已有核验材料保留在历史证据中，无需作为界面指标或答辩专题。

## 仍然保留的完成度

- 完整覆盖2017年5–8月和302站，继续回答时间高峰、繁忙站点、早晚进出、出行类型、天气关联五个问题。
- 六页中文界面、离线站点地图、日期和站点筛选、CSV/PNG导出。
- KMeans站点分组及真实评价，配平均曲线、地图和代表站解释。
- 统一字体、颜色、留白和图例；每页采用“问题—关键数字—主图—简短结论”的顺序，方法细节可展开查看。
- Windows拷贝即用、无需现场安装Python、断网可演示；代码ZIP不超过30MB，便携环境单独打包。
- 完整课程报告、PPT、四份个人调研、真实AI记录、四人各25%的计划分工和原截止时间。

地图、清洗、描述性统计、客流与出行模式分析属于课程要求，继续保留。聚类属于已选择的增强，精简其实现与评价方式。Python和依赖版本、数据单位、统计分母等决定复现和结果正确性的内容继续写清，不必全部摆在主界面上。

## 聚类简化后的边界

使用四个月有效数据描述现有站点的出行模式；基准设定是分3组，同时比较2、4、5组的轮廓系数。保留工作日/非工作日、进站/出站曲线，固定计算设置，现场不训练。

组数选择与轮廓系数都来自同一批数据，因此报告只能说明这批站点的分组情况，不能声称完成了独立测试或具备未来预测能力。较弱的分组结果也应如实解释。
