启动：用户完整解压后双击启动器；从启动器自身位置定位包内解释器，以`python.exe -m streamlit run`启动，仅绑定127.0.0.1；等待服务就绪再打开浏览器。后台进程使用隐藏窗口；提供可见的启动状态/错误说明和停止方式。目标机不运行pip、不需要预装Python、不修改系统PATH。

环境：保留包静态资源、dist-info、科学计算DLL和许可证；用`python313._pth`约束路径，避免误用本机Python。必要VC/OpenMP依赖必须合法随包且经实测；不能把现场安装运行库作为成功条件。

离线：数据、图表脚本、字体及必要地图资源本地化，启动不自动下载文件。地图采用发布坐标的站点分布与邻接连线，真实地理参考底图只在坐标一致性核查完成后加入。不能把相邻站连线当作真实线路曲线或OD流向。

PNG：图表工具栏用浏览器Plotly导出，报告可用Matplotlib Agg批量生成。避免引入Kaleido及其额外Chrome依赖。中文字体和地图背景是否完整必须在断网导出时实测。

## 4. 聚类方案候选

目的：对问题C的站点客流曲线进行分组，解释相似时段模式及空间分布。聚类对象是站点，最多302个；没有真实类别目标变量。不对个人身份、住所或职业进行推断。

特征：每站在有效工作日、有效非工作日上的平均小时进站曲线及出站曲线。06:00–23:00的17个完整小时×2个方向×2类日期，共68维候选特征；实际源文件必须确认时段覆盖，不能用理论时段覆盖伪造完整记录。每个日期类型内部，以该站17小时进出总和归一化34维向量，两类日期同权拼接，突出形状，客流绝对规模另作解释变量，不混入聚类距离。

缺失：只使用按质量规则有效的完整时段；不能用0代替缺失。任何训练/验证/测试分区缺少所需完整曲线的站点，要记录排除原因并在界面保留“未参与该次模型评价”状态；不为凑302站补造数据。

拟合与选择：

1. 2017年5–6月作为拟合期，7月作为选择期，8月作为独立评价期。各期先排除已确认的异常缺失日期。
2. KMeans主方法：候选k=2,3,4,5,6；init=k-means++、n_init=20、random_state=42。
3. 基线：相同特征、相同k的Ward层次聚类。Ward没有原生predict，明确用拟合期各簇均值构成最近中心分配器来评价后续月份；报告不能将此扩展说成原生Ward预测功能。
4. 用5–6月拟合的KMeans中心给7月站点曲线分组，在有效且至少有两组的结果中，以7月轮廓系数最大选择k；数值在1e-6内视为并列，取更小k。记录所有候选的轮廓系数、Davies–Bouldin指数和簇大小，不删除不理想的对照结果。
5. k确定后，在5–7月重新拟合最终KMeans及同k的Ward基线；8月只用于评价，禁止看8月结果后修改k、特征或质量规则再冒称独立测试。

评价：最终KMeans和Ward最近中心分配器分别对8月特征给出标签，报告轮廓系数（越高越好）与Davies–Bouldin指数（越低越好），附簇大小与中心曲线。单簇、单样本簇等导致指标未定义时显示不适用并解释。另用随机种子0、21、42在同一5–7月特征上重复KMeans，记录ARI衡量初始化稳定性；它不是真实类别准确率。

系统：展示5–7月拟合出的固定站点分组、归一化中心曲线、各簇代表站和空间分布、模型所用日期/参数以及8月评价表。日期筛选改变统计视图，不隐式重新训练或改变固定标签；切换簇可查看站点。所有计算离线预先完成，答辩不训练。

解释边界：标签先用“早进晚出型”等曲线描述，不能仅凭聚类证明住宅区/商务区的实际用地；若基线表现更好或聚类重叠明显如实写入结果与总结。本项目不设置必须达到某个漂亮分数的验收条件。

## 5. 可执行数据验证门槛

- 对Figshare ZIP先读中心目录获取文件位置/长度，不能把本次观测偏移写成永久不变的下载算法。支持Range时仅提取所需CSV；不支持时给出整包下载后选择性提取方案。
- 本次观测：进出文件压缩50109160字节，解压217442845字节，ZIP声明CRC32=7f82d0c5。正式提取验证压缩长度、解压长度、CRC，并记录来源/版本/SHA256。
- 实际进出13列为date,timeslot,startTime,endTime,station,inFlow,outFlow,CinFlow,HBOinFlow,NHBinFlow,CoutFlow,HBOoutFlow,NHBoutFlow；源表头去首尾空白。
- date和startTime/endTime保留前导零再解析；首条timeslot=0对应06:00，不据slot直接猜跨天日期。候选唯一键(date,startTime,station)，需实测重复情况。
- 检查非负整数流量、分项加和、站点关联、时间顺序、10分钟区间、已知缺失日、全部站点与日期覆盖。规则触发量真实记录，不能人为制造缺失或异常案例写入数据报告。
- 天气原始列temperature_2m,apparent_temperature,rain,wind_speed_10m的物理单位还须核验作者请求参数/服务文档，核验前不在图上标注未经证实的单位。
- 完整原始记录数、有效记录数、清洗前后缺失/重复/异常量、实际小时/日汇总数在全文件读取后自动生成。它们当前未知，不用理论乘积冒充实测样本数。
- 聚合后数据按无损整数类型和列裁剪存储；最终源码ZIP≤30MB必须实测。若超出预算先剔除重复中间产物、优化格式；如仍需减少已确认的时间/站点范围则重新提出范围变更，不能静默抽样。
